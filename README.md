# 广工漫游 · 大学城校园地图

一个可在本机浏览器运行的 Three.js 微缩校园。包括教学区、生活东区、生活西区，96 个已建地点、2 个默认隐藏的规划地点。图书馆、南门组团、体育馆、文化活动中心等采用独立参数化模型。

在线体验：https://gdut-campus-atlas.gdut-campus-atlas.workers.dev

源码仓库：https://github.com/Xuezhenggdut/gdut-campus-atlas

## 打开与关闭

1. 双击项目根目录的 **START-CAMPUS.cmd**。浏览器自动打开本地网页。
2. 完成后双击 **STOP-CAMPUS.cmd** 关闭服务。关闭浏览器标签本身不会停止服务。
3. 已经启动时再次双击，会打开现有服务。默认端口 4173 被占用时自动尝试后续端口；实际地址保存在 `.runtime/server.json`。

也可在项目目录运行 `npm run preview`，然后打开终端显示的地址；按 Ctrl+C 停止。

无需 Blender，无需账号、在线 AI 服务、地图 API 密钥或服务器。当前已安装 Node.js v24.16.0，依赖与 `dist/` 已准备好。核心地图可在断开互联网后通过本地服务运行；资料来源链接是外部网页，需要联网查阅。请勿直接双击 `dist/index.html`，浏览器应通过本地 HTTP 服务加载模块。

Cloudflare 预览可运行 `npm run preview:cloudflare`，发布新版本运行 `npm run deploy`。

## 操作

- 鼠标左键拖动旋转、滚轮缩放、右键拖动平移。触屏一指旋转、双指缩放和平移（采用 Three.js OrbitControls）。
- 搜索名称、部分文字、宿舍编号或别名，例如“工大魔方”“教一”“东十一”“西三饭堂”。回车定位首个匹配结果。
- 使用区域页签、分类、总览、俯视和北向复位按钮浏览；点击建筑、名称或列表选择同一个地点。
- 地图图层中可切换名称、规划项目和二维模式。二维模式保留搜索与地点详情。
- 日间/黄昏切换光照；校园漫游按 8 个地标巡游，拖动或缩放立即中断。
- 手机底部可展开地点列表；选中卡片可展开和收起详情。
- `?place=library` 等链接恢复地点；未知 ID 显示正常总览。`?2d` 直接进入二维模式。
- Canvas 获得焦点后方向键平移，+/- 缩放；控件支持 Tab，Escape 关闭浮层并暂停游览。

## 文件说明

| 路径 | 内容 |
|---|---|
| `src/data/campus.ts` | Place、Building、Source、坐标转换、搜索、游览顺序 |
| `src/data/landscape.ts` / `road-routes.json` | 区域轮廓、道路引导线、已避让建筑的道路中心线、湖岸与岛屿 |
| `src/scene/models.ts` | 各类建筑的参数化生成器及图书馆四面立面编码 |
| `src/scene/CampusScene.ts` | 渲染、实例树木、相机、拾取、分级标签、模型导出 |
| `src/App.tsx` / `src/styles.css` | 中文界面、移动布局、搜索和信息卡 |
| `models/library.glb` | 图书馆单体模型，原点居中 |
| `models/culture.glb` | 文化活动中心单体模型，保留弧形前厅及屋顶组合 |
| `models/south-gate.glb` / `gym.glb` / `cricket.glb` | 南门入口组团、体育馆及看台、板球场模型 |
| `models/gdut-campus.glb` | 已建校园建筑集合，保持示意坐标；不含树木、地形、湖面和道路 |
| `output/campus-data.json` / `地点清单.tsv` | 可查阅的完整数据导出 |
| `output/地点ID标注图.svg` | 自绘位置与稳定 ID 对照图 |
| `output/asset-manifest.json` | 区域与导出资产清单 |
| `output/` | 展示截图、性能原始数据与浏览器检查记录 |
| `docs/素材与简化说明.md` | 参考来源、使用方式及还原边界 |
| `docs/验收报告.md` | 验证结果与未达到的项目 |
| `research/` | 用户 PDF 与研究资料缓存，未打包进网页 |

网页“关于地图”还可随时导出 GLB；导出过程会立即重新加载文件验证几何及材质。GLB 坐标单位是示意单位，不代表米。导出保持几何原始精度，文件大于网页程序属于正常情况：网页通过本地代码生成这些几何。

## 维护

修改地点名称、别名、介绍、类别和来源：编辑 `src/data/campus.ts`。稳定 ID 不应因改名改变。一栋建筑可以关联多个地点，例如图书馆与校史馆。

修改建筑外形：调整 Building 的宽、深、高、朝向等参数，或编辑 `models.ts` 中对应生成器。高度均为估计，`heightBasis` 记录其性质。不要把 PDF 上标签或屋顶中心当作地面落点；坐标约定见数据文件。

教学科研区道路在 `src/data/landscape.ts` 维护，生活区校准路网在 `src/data/planningCalibration.ts` 维护。当前采用共享规划图坐标和已核对的连接关系；旧 `route-roads.py` 仅是历史维护工具，不应直接覆盖当前手动校准路网。

修改后执行：

```powershell
npm run build
npm test
npm run export:baseline
```

开发时运行 `npm run dev`。重装开发环境使用 `npm ci`，版本以锁文件为准；要求 Node.js 22.12+。重新生成 GLB 可在更新后的网页“关于地图”导出。

### 还原边界

这是校园示意模型，不是测绘级数字孪生。布局以用户提供的官方插画 PDF 为基准，外形参考大学城校区官方照片；部分建筑只具备插画轮廓依据。立面、层数、高度、背面、绿化位置和小路均有概括。食堂缺少已核实的多角度实景外观，尚未达到精确外观验收要求。详情见素材说明和验收报告。

未包含室内、实时定位、步行路线、真实距离/步行时间、实时开放状态及公网部署。官方照片未作为贴图或网页配图分发。`research/` 仅用于本地参考，分享网页只需 `dist/`；分享研究照片需另行确认其授权。
